# PE UK source checklist: uk-data targets → Chronicle packages

Tracker for the migration of every calibration-target family in
`policyengine-uk-data` (pinned ref for the migration:
[`ebf733c`](https://github.com/PolicyEngine/policyengine-uk-data/tree/ebf733c6ee7c0cea0afa7098bf4fbbe9922814bb),
2026-07-26) onto Chronicle source packages. Scope issues:
[#132](https://github.com/PolicyEngine/chronicle/issues/132) (wave 1, production
149-target surface), [#133](https://github.com/PolicyEngine/chronicle/issues/133)
(wave 2, remaining national registry + `uk_national` profile),
[#134](https://github.com/PolicyEngine/chronicle/issues/134) (wave 3, local
geography).

Status vocabulary:

- **ported** — the publisher's facts live in the linked Chronicle PR.
- **excluded (computed)** — the uk-data value is PolicyEngine-computed
  (uprating, flat-fill, share-split, rate×count product, cross-source
  composition); the facts-only ADR (`docs/adr-chronicle-facts-only.md`) keeps it
  out of Chronicle and the computation becomes a populace-side declaration.
  Where the row says **base facts ported**, every publisher input the
  computation needs is in Chronicle, so a consumer can rebuild the value
  without Chronicle having computed it.
- **no publisher column / no publisher measure** — the artifact is pinned and
  parsed, but the publisher simply does not print the quantity uk-data uses.
  Resolving the affected target is a profile decision, not a sourcing gap.
- **blocked** — the publisher source cannot be obtained (lost, never cited, or
  never published as a table), so the family stays out of Chronicle until a
  source surfaces. Each blocked row states what was tried.

"Source reuse / notes" says whether the Chronicle package ingests the
byte-for-byte artifact uk-data used, or had to re-pin because uk-data's source
was runtime-downloaded, link-rotted, or transcribed from a page.

## Target families — full inventory

One table for every calibration-target family in uk-data, national and local.
The local families (constituency and local-authority grain) emit no registry
`Target()`s: they are loss-matrix inputs read from committed per-area CSVs, so
their parity is measured against
`datasets/local_areas/{constituencies,local_authorities}/loss.py` and
`targets/sources/la_council_tax.py` rather than against the target registry.

Every family below is either **ported**, **excluded (computed)** with its
publisher base facts ported, or **blocked** with the reason the publisher source
cannot be obtained. Nothing in uk-data is absent from this table.
